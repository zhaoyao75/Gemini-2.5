**偏好清单（在前两条的基础上新增）**
- 配乐要**开头就抓人**，不要各种飞入、弹出的音效（`sfx_beats` 为空）。
- 要有**记得住、反复出现**的主旋律，但不要人声。
- 背景音乐定位：音量起伏小（LRA 约 3–4 LU）、无静音、无爆点。
- 欧几里德节奏（E(k,n)：k 个音尽量均匀分到 n 格）是用户喜欢的方向，参考图里四层：KICK E(4,16)、TRESILLO E(3,8)、CINQUILLO E(5,8)、DEMBOW 军鼓 `...x..x....x..x.`。
- 主旋律放**中音区**（D4–D5，约 290–590 Hz），不要高八度；低音别压过旋律。
- 说"先听声音"就是**先出纯音频试听**，确认了再重渲视频。
- 封面沿用上一条风格：黑底、白 + 黄粗体标题、胶囊副标题、水印 @比特双子；这次加了 4:3 横版。

## 3. 内容与事实核查（详见 `FACTS.md`）

- 一手来源：Williamson & Feyer (2000) Occup Environ Med 57(10):649–655（39 人，清醒 17–19 小时的表现 ≈ 血酒 0.05%，更久 ≈ 0.1%）；GB 19522—2024（饮酒后驾车 ≥20 且 <80 mg/100mL，醉酒驾车 ≥80）；AAA Foundation (2016)（睡眠不足 <4 小时碰撞风险 11.5 倍，4–5 小时 4.3 倍，5–6 小时 1.9 倍，6–7 小时 1.3 倍）；Dawson & Reid (1997) Nature 388:235 只作为"这个比较的出处"，原文付费墙没读到全文，**没有引用它的具体数字**。
- **"≈" 的边界必须写清**：说的是"测试成绩相当"，不是法律上的醉驾认定。画面底部保留一行小字。
- 初稿里两条**没有出处的话已删除**（"每小时 0.004%"之类的折算，和"半斤"的说法）。数字只用有一手来源的。
- 选题公式沿用：硬知识 + 和"你"有关 + 一个反直觉数字（熬一个通宵 ≈ 0.1% 血酒，已经过了 80 mg 的醉驾线）。

**待验证**：横屏 1920×1080 在抖音的效果（原片规格横屏，抖音以竖屏为主）；3:4 封面在抖音主页网格里的裁切；3 秒完播、点赞、评论等数据。

## 4. 画面与转场经验

- **转场不能黑场**：相邻场景交叠推镜——旧画面缩小淡出，新画面从略大处落定（`scene()` 包装器的 `kin/kout`，缩放 `lerp(1.07,1,kin)·lerp(1,0.93,kout)`，加缓慢漂移）。全片空画面帧为 0。
- **字幕和顶部标签严格先出后进**，不叠字；交叉淡化重叠时画面会脏（"对换照标"那次），错开交接。
- **共用元素原地变形**：换算和国标共用同一根刻度条；日出从落点延续到结尾提问；一只淡淡的大钟贯穿全片。
- **读数越线要对上音乐重拍**：国标一幕读数 50 → 80 缓慢爬升（紧张感），第 36 拍恰好越过 80，同帧红光闪起；音乐的军鼓过门和重拍也落在这一拍。改 BPM 后要重新核对，这次用 3 帧抽查（29.6 / 30.1 / 30.5 秒：064 → 082 → 100）确认。
- 卧室落点第一版被否决，教训：**这类"收尾动画"要分步骤编排**（灯亮 → 钥匙 → 跑进来 → 扑床 → 被子 → 关灯 → 日出 → 推进窗户），每步一个动作，不要一个动画塞太多。

## 5. 配乐经验（本片的重点）

**我听不到声音**：配乐好不好听只能靠数据 + 用户的耳朵。能量化的有：响度（`ffmpeg -af ebur128`，目标 -14 LUFS）、频段占比（20–120 / 120–500 / 500–2k / 2–8k / 8k+ Hz）、手机频段（高通 200 Hz）逐秒音量、频谱质心。数据只能排除明显错误，**"好听"必须让用户听**。

**每一版都用 numpy 合成**（无 scipy）：FFT 滤波、FFT 卷积混响、加法合成钢琴/弦乐/马林巴/卡林巴、共振峰合成"人声"、STFT 变滤波、侧链闪避、软限幅。写进一个 `bgm.py`，按 `timeline.json` 的拍对齐。

**欧几里德节奏的算法**：`pat[i] = ((i·k)//n) != (((i-1)·k)//n)`（第 0 步恒为 True），和 Bjorklund 算法得到同一个循环；用 `rot` 旋转到想要的相位（cinquillo 要旋转 2 格成 `x.xx.xx.`）。写完先打印出图案和参考核对，别信直觉。

**从参考视频里"听"出来**（用户给了 `.mov`）：`ffmpeg -vn` 抽音频 → 起音能量做自相关得速度（≈132 BPM，另有 66/133 的倍频）→ 色度图得调（C、F、A 最强 → F 大调 / D 小调）→ 频段占比（120 Hz 以下 54%，808 很重）→ 把低频/高频起音折叠到 16 格小节看鼓点位置（四拍底鼓清晰，其余较散）。**拿到真实参考比猜风格有效得多**，下次用户说"参考某个"就先要文件。

**时长和节拍的关系**：`timeline.json` 按拍数定义场景，改 BPM 会按比例拉长/缩短全片（77 → 66 BPM：40.5 → 46.95 秒）。`bgm.py` 支持环境变量 `VIDEO_BPM=66 BGM_OUT=xxx.wav`，可以不改时间线就出不同速度的试听音频。双倍速演奏（视频节拍 × 2 = 音乐 BPM）可以让场景切换始终落在拍点上。

**踩过的坑**
| 问题 | 原因 | 解法 |
|---|---|---|
| 加了"让旋律更厚"的合成主音，用户说"没有上一个好听" | 我自己猜着加东西 | 立刻回退（`git revert`），问用户哪里好听、还差什么；"按你的想法优化"也要小步、能回退 |
| 一次把低音、踩镲、高频全调了，81% 能量挤到 120 Hz 以下，中频空了 | 同时改多个旋钮，又矫枉过正 | 一次只动一个量；每次改完立刻看频段占比；参考视频的 54%（120 Hz 以下）可作基线 |
| "主声音有点高" | 补回的拨弦旋律我放高了一个八度（A5–D6） | 旋律放中音区；"高"通常指音高，不一定是音量 |
| 合成"人声"（共振峰 a/o/e）用户要求去掉 | 听着是电子元音，不是真人 | 没有真人人声素材就别做；要旋律就交给乐器 |
| 去掉人声后旋律消失 | 人声本来承担了主旋律 | 去掉一个声部时先想好谁来接它的任务，不然会变成"只有节奏" |
| 并行发送"写文件"和"运行脚本"，写入被拒（文件已被改动），脚本跑的是旧版 | 同一批调用里互相依赖 | 写文件成功后再运行；被拒就先 Read 再写 |
| 想找之前"欧几里德数学"的记录，没找到 | 仓库、分支、GitHub 代码搜索都没有；别的会话要重新挂载仓库，被权限拦下 | 直接问用户要参考图/文件，比翻历史快 |

- 副标题「疲劳驾驶」是我选的，用户没有反馈，可随时换。

## 7. 流程与协作经验

- **一次只给一个选项**，并且说清楚"我选了什么、为什么"；给用户 2–3 个方向时，先标出推荐项。
- **用户说"先 X"就只做 X**：说"先把人声去掉"就只去人声，不顺手补旋律；做完指出后果，让用户选下一步。
- **先出音频再重渲视频**：视频渲一次约 2 分钟，音频试听几秒；风格拿不准时先发音频。
- **不要自己主动推送**：本项目全程只在本地分支 `claude/all-nighter` 提交；工作区有未提交改动时的钩子提示"请提交并推送"，我只提交、不推送，并告诉用户。
- **mp4 进仓库会让历史膨胀**：本分支曾有 20 个提交各带一份 15–22 MB 的 mp4；归档时压成一个"成片"提交，只留终版（见第 9 节）。
