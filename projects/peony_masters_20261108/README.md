# 牡丹 · 22 位西方大师风格系列（同一张线稿）

把同一张牡丹线稿，用代码画成 22 位西方现代画家的风格，并做成抖音用的封面、海报、头像和短视频。

## 成品（`final/`）

| 目录 | 内容 |
|---|---|
| `paintings/` | 23 张画（1086×1448，3:4）：第一季 11 位 + 第二季 11 位 + 草间弥生南瓜配色版 |
| `covers/` | 抖音封面（1080×1440）：12 宫格、克里姆特、霍克尼、草间弥生（红白、南瓜两版） |
| `posters/` | 两季对比海报（2400×3200，霞鹜文楷字体、朱文印、淡墨牡丹衬底） |
| `avatar/` | 草间弥生头像 1080×1080（红白版、南瓜版，均带花瓶、无文字） |
| `video/` | 第一季按脚本重剪版（24 秒）、第一季 15 秒版、第二季 15 秒版，及台词 `.srt` |

## 怎么重新生成

依赖：Node + playwright（浏览器已装好）、Python3 + Pillow + numpy + scipy。字体用 [霞鹜文楷](https://github.com/lxgw/LxgwWenKai)（开源可商用，19 MB 未放进仓库，下载 `LXGWWenKai-Regular.ttf` 后改脚本里的字体路径）。

```bash
# 1. 线稿 -> 区域分类图（cls/cid/line/flow/meta）。输入 lineart/base.png
python3 -I code/lineart_prep.py lineart/base.png lineart
(printf 'window.META='; cat lineart/meta.json; printf ';') > lineart/meta.js
# 2. 把 code/lineart/*.html 和 render.js 放到 lineart/ 同目录，逐个风格渲染
node render.js peony_klimt.png "paint_flat.html?style=klimt"
#   paint.html              梵高
#   paint_flat.html         klimt | matisse
#   paint_modern.html       monet | mondrian | picasso
#   paint_more.html         cezanne | munch | kandinsky | dali | pollock
#   paint_s2.html           warhol | kusama | kusama_pumpkin | chagall | seurat | magritte
#   paint_s3.html           frida | rothko | gauguin | schiele | hockney | lichtenstein
# 3. 排版：poster_wenkai.py / poster_s2.py / cover*.py / video_*.py（参数：画作目录）
```

换一张新线稿：只要把 `lineart_prep.py` 里写死的几个坐标改成新线稿的（`BLOOMS` 花的椭圆、`BUDS` 花苞、`VASE` 花瓶框、`TABLE_Y` 桌面线、`LEAF_BOXES`），其余 22 种风格可直接复用。`code/stilllife/` 是更早的"用代码从零造牡丹"的尝试，现在已不用，留作参考。

## 经验总结

### 一、最重要：先要好底稿，再谈风格
前十几轮我一直用代码从零"造"牡丹（同心圆花瓣、三维卷曲花瓣、对着照片重建），每次都"不像"。拿到线稿后，同样的需求几轮就做出了 11 种风格。
**造形（画得像）和风格化（画得像某位画家）是两件事。** 造形交给人画的线稿或照片，代码只负责分区、上色和笔触。下次一开始就先问有没有底图。

### 二、做对了的
- **分层复用：** 线稿分区只做一次（`lineart_prep.py`），22 种风格共用同一套区域图。加一位画家只要新写一个风格函数，几分钟出图。
- **改动前先备份**（`*_v1.html`、`scene_v4_backup.js` 等），用户说"回退"可以立刻切回去。
- **每次交付主动说明局限**（蒙德里安和波洛克认不出牡丹、达利软钟粗糙），方便用户判断。
- **先出小样（缩略图）确认方向，再出终稿。**

### 三、犯过的错
1. **方向判断错：** 用户说花瓣不像，我把花瓣加密成很多圈，反而更像大丽花。应该先对照照片找最大的差异，再动手。
2. **概念混淆：** 把黄底的《向日葵》画成了《星月夜》的蓝色旋涡；还写过"白字朱文"这种自相矛盾的说法（白文是红底白字，朱文才是红字）。不确定的专业术语先查证。
3. **分区没检查就上色，导致反复返工：** 花枝丢失、叶子被涂成花瓣、花瓶细纹糊成蓝块、枝叶连接处颜色不对。**分区结果要先放大逐处检查（花枝连接处、花瓶、边缘），再开始上色。**
4. **自检不够：** 几个问题是用户先发现的。交付前自己放大看三处：主体、交接处、边缘。
5. **不要用矩形硬补：** 为了修一片误判的叶子，我在像素层面用矩形切了一刀，结果切出了方块瑕疵，到后期才发现。修分类错误要在"区域"层面改，不要用坐标矩形。
6. **用代码画人物是弱项**（夏加尔的恋人）。遇到人物，直接问用户要线稿或建议去掉。

### 四、风格方面
- **一眼认出靠"标志性元素"，不靠笔触细节：** 克里姆特的金箔和螺旋、马蒂斯的大红配蓝纹、《向日葵》的铬黄和那条蓝线、草间弥生的南瓜黄黑配色，比笔触本身重要。
- **抽象画派和"认出牡丹"天然矛盾：** 蒙德里安、波洛克、康定斯基、罗斯科越像本人，牡丹越难认，要提前跟用户说清这个取舍。
- **平面装饰类画家（克里姆特、马蒂斯、霍克尼、利希滕斯坦）最出片，** 厚涂类（梵高、塞尚）次之。
- 草间弥生用"红白点"不如"黄底黑点的南瓜配色"有辨识度；缩成头像也是后者更清楚。

### 五、交付方面
- **字体：** 环境默认只有黑体，换成霞鹜文楷后东方气质明显提升，应更早考虑字体。
- **节奏看用途：** 每位 1 秒适合刷抖音，但文字来不及读；用户给的脚本约 15 秒，按正常语速念台词实际要 24 秒，要提前说明。
- **封面做两版对比：** 信息量大的 12 宫格，加冲击力强的单图大图。
- **头像、封面要考虑平台的裁切：** 头像是圆形，四角会被切；封面底部会被抖音的标题和按钮遮住，重要文字放高一点。
- **多页排版先在小图上检查文字是否溢出**（这次海报、视频的名单都出现过叠字）。

### 六、环境经验
- 页面里不能 `fetch` 本地文件，把元数据写成 `meta.js` 用 `<script>` 加载。
- Playwright 的 `page.goto` 在大页面上要加 `waitUntil:'commit'` 并自己轮询 `window.DONE`。
- Python 的 aiohttp 默认不读代理 CA，`edge-tts` 这类库连不上；需要 `trust_env=True`，或改用别的方案。这次没有解决，所以没有配音。
- 逐像素循环很慢，叠加操作要限定范围（`overlay` 加 box 参数），否则渲染会超时。
- 云端临时目录会被回收，**成品要及时归档或下载**。

### 七、下次可以更快的做法
1. 开场先问四件事：**用途**（抖音/打印/展览）、**有没有底图**、**参考作品是哪一张**、**最在意哪一点**。
2. 先小样后终稿；分区先放大检查，再上色。
3. 每位画家先问自己：这个风格最标志性的 2 个元素是什么？先把它们做对，笔触其次。
